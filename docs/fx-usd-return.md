# 달러 기준 수익률 (환율 효과 제외)

원화 수익률에는 원/달러 환율 변동이 섞입니다. 개미장부는 같은 기간을 달러로 한 번 더 계산해서, 환율을 빼고 본 수익률(`return_usd`)과 그 차이(`fx_effect = return - return_usd`, "환율 영향")를 같이 보여 줍니다.

## 계산 방법

같은 수정 디츠(Modified Dietz) 계산을 장부 전체를 달러로 바꾼 뒤 한 번 더 돌립니다(`metrics.in_usd`).

- **평가액**: 그 평가액이 계산된 환율로 나눕니다. 스냅샷에 환율(`snapshots.rate`)이 있으면 그 값을, 없으면 그날(또는 그 직전) `fx` 표의 환율을 씁니다.
- **입출금·배당**: 그날 `fx` 환율로 나눕니다. 계좌 자체 환율은 쓰지 않습니다. 그래야 같은 날 내 계좌끼리 옮긴 돈이 합계에서 서로 지워집니다.
- **원화 전용 계좌**(예금·적금, `ASSETLOG_PRINCIPAL_ONLY`)는 고정 환율 하나로 바꿉니다. 환율 노출이 없는 돈이 달러 기준에서 이익이나 손실처럼 보이지 않게 하려는 것입니다.
- 첫 환율보다 앞선 기록은 달러 계산에서 빠지고, 그 계좌는 처음 환산할 수 있는 시점부터 들어옵니다. 원화와 달러의 계산 구간이 달라지면 두 값을 비교할 수 없어서 달러 값은 비워 둡니다(`null`).

"평가액을 기간 시작 환율로 다시 계산"하는 더 단순한 방법은 쓰지 않습니다. 기간 중에 원화를 넣고 환전하면 `입금액 × (시작 환율 / 환전 환율 − 1)`만큼 가짜 손익이 생기기 때문입니다.

## 환율 데이터

- 매일 동기화할 때 한국투자증권(매매기준율)과 토스증권(midRate)이 그날 환율을 `fx` 표와 스냅샷에 남깁니다.
- 동기화를 시작하기 전의 과거 기록이 있다면 `python3 -m assetlog backfill-fx`가 장부에 이미 있는 값(한투 배당 기록의 환율, 토스 거래내역서의 환율 칸)으로 `fx`를 채웁니다. API 호출은 없고, 여러 번 실행해도 결과는 같습니다.
- 직접 입력한 월말 평가액이 있다면, 그때의 환율을 `data/fx_month_end.json`(`{"YYYY-MM-DD": 원}`)에 넣어 두면 함께 채워집니다.

## 한계

- 원화 예수금은 달러로 환산되므로 그 부분만큼은 환율 영향이 남습니다.
- `fx_effect`는 두 수익률의 차이입니다. 교차항과 입출금 시점 효과가 섞여 있어서 순수한 환차손익과는 조금 다릅니다.
